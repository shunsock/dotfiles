# PR 説明文の評価方法 (共有)

PR 説明文を skeptical-reviewer で評価するときに注入する評価方法である。
`write__pull_request` (セルフチェック)・`submit__pull_request`・`restart__pull_request` が single source of truth として参照する。
生成された説明文を、実際の diff・コミット履歴・参照先と突き合わせて反証する。

## 評価の姿勢

- 説明文の主張・前提が成立しない可能性のある箇所だけを挙げる
- 説明はすべて実際の差分から導出されるべきである。差分・履歴 (`git diff` / `git log`) を一次データとして裏取りする
- 裏取りできない指摘は根拠に「未検証」と明記し、推測で断定しない

## 評価観点

| 観点 | 検査内容 |
|---|---|
| Why の明確さ | 「なぜこの変更が必要か」が冒頭で伝わる |
| 事実の正確性 | 説明された変更が実 diff に存在する。存在しない変更・変更のない箇所への言及がない |
| 変更箇所の網羅 | 主要な変更ファイルが `パス: 内容` 形式で挙がり、diff との突き合わせで欠落がない |
| 選択肢の比較 | 採用しなかった代替案に言及している。採用案だけを持ち上げる偏った記述がない |
| トレードオフの開示 | 意図的に受け入れた妥協点が記述されている (なければ「無し」と明記) |
| 確認事項の明示 | 意思決定事項が ⚠️ 付きでレビュアーに伝わる |
| 参考文献の健全性 | リンク切れ (404・到達不能) がない。各リンクが PR と実際に関連する |
| テンプレート整合 | `~/.claude/skills/template/pull_request.md` の構成に従い、テンプレートの HTML コメントが残っていない |

## restart 固有の追加観点 (restart__pull_request から呼ばれた場合のみ)

| 観点 | 検査内容 |
|---|---|
| 議論の統合の正確性 | 「却下された案」「取り込んだレビュー指摘」の要約が旧 PR の実際の議論と一致する (`gh api` で旧 PR のコメント・レビューを裏取りする) |
| 引き継ぎの網羅 | 旧 PR の未解決指摘・別 PR 対応の合意事項が「確認事項 / 残課題」から欠落していない |
| 参照の明示 | Supersedes として旧 PR の URL が明記されている |

## 出力形式 (本評価方法が指定する)

既定の反証表 (指摘 / 深刻度 / 根拠 / 確度) で出力する。
末尾の「反証を試みたが壊せなかった点」に続けて、次の判定行を追加する。

- `Verdict: pass` — 深刻度が高または中の指摘が 0 件の場合
- `Verdict: needs_fix` — 深刻度が高または中の指摘が 1 件以上の場合
