# 実装計画の評価方法 (implement__feature)

`implement__feature` スキルが Phase 1 の計画提示後、実装着手前に skeptical-reviewer へ注入する評価方法である。
Implementation Plan (作業単位・テストサイズ・依存・テストリスト) を、対象リポジトリの実コードと突き合わせて反証する。

## 評価の姿勢

- 計画の主張・前提が成立しない可能性のある箇所だけを挙げる
- 変更対象ファイル・既存コードへの言及は、リポジトリの実コードで裏取りを試みる
- 裏取りできない指摘は根拠に「未検証」と明記し、推測で断定しない

## 評価観点

| 観点 | 検査内容 |
|---|---|
| 実コードとの整合 | 変更対象ファイルが実在する。計画が前提とする既存の関数・型・設定が実在する |
| タスクとの整合 | 作業単位の合計がタスク (issue / 指示) の要求を過不足なく覆う。範囲外の作業が紛れ込んでいない |
| 見落とし | 既存の類似実装・ユーティリティで置き換えられる作業単位がないか。影響するが計画に含まれないファイルがないか |
| テストサイズの最小化 | small テストで検証できる作業単位が medium / large に割り当てられていない |
| テストリストの網羅 | 各作業単位のテストリストが、その範囲の主要な振る舞いと境界を覆う |
| 依存関係の成立 | 依存の記載が実装順として成立する。並行可の指定に共有ファイルの競合がない |

## 出力形式 (本評価方法が指定する)

既定の反証表 (指摘 / 深刻度 / 根拠 / 確度) で出力する。
末尾の「反証を試みたが壊せなかった点」に続けて、次の判定行を追加する。

- `Verdict: pass` — 深刻度が高または中の指摘が 0 件の場合
- `Verdict: needs_fix` — 深刻度が高または中の指摘が 1 件以上の場合
