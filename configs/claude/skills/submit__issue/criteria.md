# Issue 本文の評価方法 (submit__issue)

`submit__issue` スキルが起票前に skeptical-reviewer へ注入する評価方法である。
issue-writer が生成した本文 (TITLE 行つき) を、要件インタビューの結論と突き合わせて反証する。

## 評価の姿勢

- 本文の主張・前提が成立しない可能性のある箇所だけを挙げる
- 事実に関わる記述 (ファイルパス・挙動・仕様) は、リポジトリの一次データで裏取りを試みる
- 裏取りできない指摘は根拠に「未検証」と明記し、推測で断定しない

## 評価観点

| 観点 | 検査内容 |
|---|---|
| テンプレート整合 | `~/.claude/skills/template/issue_acknowledged.md` の構成に従っている。条件付きセクション (バグ: 根本原因 / 機能: ユーザーストーリー) が種別どおり処理されている。埋め残しのプレースホルダや HTML コメントが残っていない |
| 受入基準の計測可能性 | 各項目が利用者・ビジネス観点で客観的に検証できる。「正しく動く」のような曖昧表現や実装手段への言及がない |
| 根本原因の裏付け (バグのみ) | 引用されたファイルパス・行番号・挙動が実コードと一致する。裏付けなく断定していない (未特定なら「調査中」と明示) |
| 要件の忠実性 | インタビュー結論にない要件を創作していない。結論にある要件が欠落していない。確認できない事実が「不明」と明示されている |
| 段階の分離 | システム要件セクション (提案手法・検証方法・作業単位・SP) が混入していない |
| 概要の自立性 | タイトルと概要だけで要点が伝わる |

## 出力形式 (本評価方法が指定する)

既定の反証表 (指摘 / 深刻度 / 根拠 / 確度) で出力する。
末尾の「反証を試みたが壊せなかった点」に続けて、次の判定行を追加する。

- `Verdict: pass` — 深刻度が高または中の指摘が 0 件の場合
- `Verdict: needs_fix` — 深刻度が高または中の指摘が 1 件以上の場合
